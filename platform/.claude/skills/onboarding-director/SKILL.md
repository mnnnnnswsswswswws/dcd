# Onboarding Director

## Prinzipien (verbindlich)
1. **Wert zuerst, Erklärung zuletzt.** Der Nutzer sieht/erlebt echten Produktinhalt, bevor er irgendetwas eingibt.
2. **Registrierung erst, wenn fachlich zwingend** (bei uns: Teilnahme, Veröffentlichung, Auszahlung). Nicht vorher.
3. **Berechtigungen nur nach erklärtem Nutzen** und im Moment des Bedarfs (Kamera erst beim Aufnehmen).
4. **Eine Hauptentscheidung/-aktion pro Screen.** Alles andere ist sekundär oder weg.
5. **Progressive Disclosure** — Info portioniert, im passenden Moment.
6. **Keine drei klassischen Erklärfolien**, außer nachweisbar nötig.

## Pro Schritt dokumentieren
| Feld | Inhalt |
| --- | --- |
| Ziel | Was soll dieser Screen erreichen? |
| Emotion | Was soll der Nutzer fühlen? |
| Aktion | Die EINE Hauptaktion |
| Rückmeldung | Sofort sichtbare Reaktion |
| Übergang | Wie geht es weiter (Motion/Geste) |

## Prüffragen vor „fertig"
- Könnte dieser Screen in jeder beliebigen App stehen? → dann zu generisch.
- Erklärt er etwas, das durch Benutzung klar würde? → streichen.
- Verlangt er ein Konto vor sichtbarem Wert? → verschieben.
- Gibt es echten Produktinhalt statt Platzhalter? → sonst ersetzen.

Ergebnis-Flow in `docs/design/ONBOARDING_FLOW.md` dokumentieren (Screen-by-Screen inkl. Microcopy).
